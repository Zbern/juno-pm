## Entry point

**Signal type:** Page or view opened

A user sign in to view pension payment history

**What they see instantly**

user is prompted for username and password; there is an option to register for an account if you have not yet

## The flow

1. RAG retrieval over HR system -> identity verification -> sign in engine -> pension payment history DB 
2. verifying employee status -> verifying identity -> signing in -> viewing pension payment history
3. Path A (request) - RAG to LLM; Path B (View only) - tool/API call to DB

## AI moments

**Placement:** Full-Page Canvas

The user should see their pension payment history, including: 
1. Date 
2. Payment ID
3. Amount
4. Payment Method (masked to last 4 digits) 
5. Source of payment 
6. option to export as CSV / PDF 
7. option to report missing payments 
8. option to report incorrect payments

The main desire of the user is to view their pension payment history, which can be accomplished with the least friction and best UI/UX via full-page canvas. AI chat functionality to explain pension payments is secondary and can be a chat bubble that expands upon click. 

## Fallbacks

**Kill switch**

report incorrect payment or missing payment option persistent on each payment entry

**Training signal**

Data mistrust -> logged as 'payment dispute" -> proactive alert of potential data cleanliness issue

**Fail-safe**

If pension DB or identity verification engine fails -> Juno goes into site maintenance mode and dispalys a maintenance message until service is restored
